# VibeMote — Remote Client Guide

> 🌐 [中文](说明.md)

Turn a **Google Chromecast / Google TV Bluetooth remote** into a talking-and-hotkey device for Windows.

| Remote button | Default action |
|---|---|
| **Voice button** (the one with the mic) | **Push-to-talk** — remote microphone → virtual audio cable → input method editor types the text |
| Up / Down | Mouse wheel up / down (**hold to keep scrolling**; a tap scrolls one notch) |
| Left / Right | `Ctrl+Shift+[` / `Ctrl+Shift+]` |
| OK / Back / Home / Power / Input source / Mute / YouTube / NETFLIX / Volume ± | See the "Key mapping" page in the UI — change them however you like |

---

## 1. What makes this build clean

- ✅ **No drivers installed** (no virtual HID, no kernel filter driver)
- ✅ **The voice part needs no administrator privileges.** Key mapping (optional) needs **one** elevation (Frida injects into the Bluetooth HID driver host); after one "One-click optimization" a highest-privilege scheduled task does it and it never prompts again. The other prompt is the virtual audio cable installer. Details in README section 5.5
- ✅ **No console windows flash**: single process + launched with the window hidden throughout, and nothing flashes on autostart either
- ✅ **No test mode, no disabling Secure Boot, no system file changes**
- ✅ **No network access** (except that one moment when you click "Install dependencies" yourself)

Three hard design rules, all of them in service of the points above:

1. **There is only one process.** Voice and keys both live in threads of the same process, with no Popen subprocesses —
   so architecturally a console window simply cannot appear. (The only place a subprocess is started is dependency
   installation, where the window is explicitly hidden.)
2. **The UI only listens on `127.0.0.1`**. Safe, and it will not trigger a Windows firewall prompt
   (listening on `0.0.0.0` is what triggers it — and it triggers it repeatedly).
3. **Configuration follows the backend `config.json`**, and the frontend does not cache or re-derive it.

## 2.1. Why does Frida trigger UAC? How to make it never prompt again

**Symptom**: while using it, a "Do you want to allow this app to make changes to your device?" prompt appears, with
`frida-helper` visible around the title; if you ignore it or click "No", it pops up again a while later.

**Cause**: key mapping relies on Frida to read the reports in the Bluetooth driver. When Frida wants to inject into a
process that is not its own, it **tries to register a temporary service** (named `frida-<PID>-x86_64`) to do this —
and registering a system service requires administrator rights, hence the UAC prompt. If it is not approved or is
interrupted midway, that service becomes a dead leftover. Retrying over and over = prompts over and over = a pile of
leftover services accumulating.

**You have to do both of these together to fix it at the root**:

1. **On the program side** (already built in): attach failures now use **exponential backoff**; after 3 consecutive
   permission failures it **stops for 5 minutes** instead of frantically retrying and spamming prompts.
2. **On the privilege side**: "Settings → **One-click optimization (prompts for administrator once)**". It will:
   - clean up all leftover `frida-*` services and helper processes;
   - switch autostart from "a Run entry with normal privileges" to "**a scheduled task with highest privileges +
     logon trigger**" — at boot the Task Scheduler starts it silently as administrator, so every permission Frida
     needs is already in place, and **from then on not a single UAC prompt will appear**;
   - delete the original Run entry, so two copies do not start at the same time and fight over the Bluetooth channel.

> If you only want to chat and talk, and do not need the D-pad/OK mappings, **just don't install frida** (don't click
> "Install key-mapping dependencies"), and this prompt will never appear at all — nor will any of the caveats below.

**Four things to know before you use key mapping** (full list in README section 5.5):

- **Antivirus may flag or silently quarantine it**: frida's module names are in several vendors' signature sets, and
  it is ~47MB of the offline bundle. Symptom: dependencies "installed" but the D-pad/OK do nothing. Whitelist the
  program folder and click "Install key-mapping dependencies" again. You do **not** need to disable Defender or
  turn on test mode.
- **It relies on undocumented interfaces**: an undocumented IOCTL of the Windows Bluetooth HID driver plus one
  registry path, and it pins `frida >=17.18,<18`. A Windows or frida update can silently break it — voice keeps
  working, key mapping is disabled and the log says so.
- **The injected host also serves your other Bluetooth keyboards/mice**: we only rewrite the reports of the mapped
  keys (erasing their native action), but if that host ever crashed, Bluetooth input would drop with it. If it
  happens, restart the client or re-plug the adapter.
- **Protected games**: the injection looks like a cheat loader to anti-cheat, so a few kernel-anti-cheat games may
  refuse to start. Quitting the client before gaming is the easy answer.

---

> **Usable right after boot**: at the moment Windows starts, the audio service / virtual audio cable is often ready
> later than the program. This program **will not give up because of that** — the voice channel retries every 5
> seconds, attaches automatically as soon as the sound card is ready, and rebuilds itself even if the connection drops
> midway. (If it only looked for the sound card once at startup, pressing the voice button after boot would never
> produce sound.)

## 2.2. Cleanup / uninstall (tick items one by one; use this when you want to reinstall from scratch)

"Settings → **Cleanup / uninstall (tick items one by one)**". **Nothing is ticked by default — tick an item and it
gets deleted; anything unticked is left completely alone.**

There are 12 tickable items (this is exactly what the UI shows; the ones marked 🔒 prompt for UAC once).
**Each item is also labelled with "does it exist right now / how big is it"** — for example, on the light package
"Delete dependencies (`.venv`)" shows "does not exist", so you are never left ticking a checkbox for something that
isn't there:

| Item | Description | 🔒 |
|---|---|---|
| Disable autostart (scheduled task) | Delete the highest-privilege scheduled task `VibeMote` | ✓ |
| Disable autostart (startup entry) | Delete `VibeMote` from the HKCU Run key | |
| Kill the client process | The voice-bridging + key-mapping process | |
| Kill the frida helper process | `frida-helper-x86 / x86_64` | |
| Clean up leftover frida services | `frida-<pid>-x86*` in HKLM | ✓ |
| Delete dependencies (`.venv`) | The bleak / sounddevice / cffi / frida you installed | |
| Delete `__pycache__` | Python bytecode cache | |
| Delete `python.txt` | The pointer file that specifies an interpreter | |
| Delete logs | `elevate_setup.log` / `client.log` | |
| Delete `config.json` | **Your key mappings will be lost**, back to the default scheme | |
| Delete the Qianwen "allow injection" switch | Once deleted, Qianwen discards injected keystrokes again | |
| Uninstall the virtual audio cable (VB-CABLE) | A **system-wide audio driver** — see the note below; unticked by default | ✓ |
| Clear virtual-audio-cable leftovers (registry / driver store) | A **repair action for when installing/uninstalling gets stuck** — see below; unticked by default | ✓ |

Three helper buttons: **Select none** / **Select "recommended cleanup"** (the 9 items above, keeping the config, the
Qianwen switch and the virtual audio cable) / **Select all**.

> ⚠ **"Uninstall the virtual audio cable" is the only item in the list that still needs a human click *and* a reboot**,
> which is why it is **unticked by default and not part of "recommended cleanup"**:
> - it is a **system-wide audio driver** that OBS, voice changers and streaming tools may also be using — removing it silences them;
> - there is **no silent uninstall**: the `UninstallString` that Windows "Apps & features" holds is the installer
>   itself with no arguments, so a human has to click **"Remove Driver"** in its window;
> - per VB-Audio's own readme, you **must reboot** afterwards to finalise it.
>
> After you tick it and start cleanup: the program prompts for UAC once and **launches the official uninstaller**;
> the last two steps (clicking Remove Driver, rebooting) are yours. The log spells this out line by line.
> The program deliberately does **not** verify "did the uninstall succeed" — reporting "not deleted" before you have
> finished clicking would be a false alarm.
>
> **"Clear virtual-audio-cable leftovers"** exists for the case where installing *and* uninstalling are both stuck:
> the registry says it is installed, but no device is enumerated and clicking "Install Driver" does nothing — the
> leftovers are blocking the new install. It removes only VB-CABLE's own entries (the two service keys,
> `HKLM\SOFTWARE\VB-Audio\Cable`, the "Apps & features" entry, the driver package in the DriverStore and
> `C:\Program Files\VB\CABLE`) and **never touches Voicemeeter's keys or folders**, even though Voicemeeter shares
> the VB-Audio vendor key. Reboot once afterwards, then reinstall. When the yellow "the virtual audio cable is not
> usable right now" banner appears on the home page, the button next to it is this action.

> ⚠ **The list deliberately has no "delete the bundled Python runtime (`runtime\`)" item.**
> It is the Python that ships with the offline package (154MB after extraction); it is part of **the program itself**,
> not an "installed dependency". And "Install all" in the UI installs pip packages, which **cannot reinstall** a
> Python distribution — once you delete it, this machine is no longer "install-free", and there is no one-click way
> back. So the cleanup tool always keeps it.
>
> **Want to uninstall the whole program completely? Two steps, and don't reverse the order:**
> 1. Here, click **"Select 'recommended cleanup'"** → start cleanup (clears autostart + leftover frida services + dependencies);
> 2. Then **just delete the entire program directory**.
>
> The program is a purely portable deployment: no installer, nothing written to system directories, so after step 2
> nothing remains anywhere on the system.

**The execution order is fixed** (not the order you ticked things in; the wrong order fails):

```
disable autostart first → then kill processes → then delete services/files → finally terminate itself
```

This matters especially for "kill the process before deleting `.venv`" — on Windows **a running `pythonw.exe` is
locked**, and reversing the order reports "cannot delete". In extreme cases (when the bundled interpreter is the
only one on the machine) the program automatically schedules a background command to continue deleting after this
process has exited (the log will say "scheduled .venv deletion… about 2 seconds"); you don't have to do anything.

**Only want to reinstall dependencies** → just click "Select 'recommended cleanup'", and `config.json` is kept.
**Want to get fully back to "never installed"** → additionally tick `config.json` and the Qianwen switch by hand (or
simply "Select all").

Command-line equivalents:

```bat
python uninstall.py --items=venv,pycache        :: delete only these two items
python uninstall.py --items=all                 :: delete everything (including config.json, the Qianwen switch and the virtual audio cable; but does **not** touch runtime\)
python uninstall.py --items=task,venv --dry-run :: list the plan only, do nothing
python uninstall.py --dry-run                   :: nothing ticked = nothing done
```

## 2.3. Which source do dependency downloads use? (installable in China without a VPN)

"Install dependencies" **automatically polls Chinese mirrors**, moving to the next one whenever one fails, and only
trying the official PyPI last. Each time it prints which source it used, so if something goes wrong you can see it
at a glance.

**This table is ranked by availability** (each one was verified to download, not copied from someone's web
recommendation):

| Order | Source | Result | Notes |
|---|---|---|---|
| 1 | Tencent Cloud | ✓ 1.1s | Fastest |
| 2 | USTC | ✓ 1.0s | The frida index is a bit slow (8.6s) |
| 3 | Aliyun | ✓ 1.4s | |
| 4 | Huawei Cloud | ✓ 1.1s | |
| 5 | TUNA | ✗ returns an empty index | Demoted to last |
| 6 | Official PyPI | ✓ 2.5s | Fallback (most reliable with a proxy / from outside China) |

> **NetEase 163 is not included**: its PyPI mirror stopped syncing long ago (bleak only goes up to 0.5.0), so
> including it would install an outdated version and produce baffling errors. Also, don't use those web configs that
> "list 8 sources at once".

**What to do if they all fail** (the program prints these three lines into the log):

1. Switch networks (phone hotspot) and click again
2. Change sources manually: edit the `PIP_MIRRORS` table at the top of `app.py` (one source per line)
3. **Fully offline**: see the `wheels\` directory in the next section — when the program detects it, **it is used
   first, with no network access at all**

## 3. How to use the UI

Five pages on the left:

- **Status**: running state, remote address, whether the voice/key channels are ready, which dependencies are missing, start/stop/restart
- **Key mapping**: **first pick a "preset" at the top** (see section 3.1); below that is a diagram laid out like the
  physical remote. Click a button → choose the **mapping type** on the right → choose the target key → save
  - Mapping types:

    | Type | Behaviour |
    |---|---|
    | `Single key` / `Key combo` | fires once on press (down and up immediately) |
    | `Hold down` / `Hold combo` | stays held while the remote button is held, released when you let go (this is what "hold to talk" needs) |
    | `Mouse` | sends one mouse action per press |
    | **`Hold mouse`** | holds the mouse: the **wheel keeps scrolling while held** (a tap scrolls one notch); left/middle/right stay pressed until you let go (for dragging) |
    | `Text` | types a piece of text on press |

  - Up and Down default to **`Hold mouse` + wheel** — a tap scrolls one notch, holding keeps scrolling; nothing to configure
  - Not sure which physical button corresponds to which item in the UI? Turn on **"Press a remote button to locate
    it"**, press a button on the remote, and the UI jumps there automatically
  - Can't fill in the target? Click **"Key capture"** and press a key on your physical keyboard — **or scroll the
    wheel / click a mouse button**. When it captures a mouse action it picks the type from the current "tap / hold"
    mode for you (scrolling while in "Hold down" gives you "hold and keep scrolling" directly)
  - Mapped buttons show right under the remote button what they are mapped to; pressing one plays an animation and
    lights an indicator in the UI
- **Voice**: voice-button target (hold / tap + modifier + main key), input method editor presets, test key send
- **Settings**: Bluetooth address + scan, audio gain / AGC / built-in microphone passthrough, autostart, environment check, install dependencies
- **Logs**: live logs; when something goes wrong, look here first

Mapping changes **take effect immediately**, no restart needed.

## 5. Copying to another computer / deploying from a USB stick

Just copy the whole `vibe-mote` folder over — **the package is under 1MB** (dependencies are installed on the target
machine).

**Route A: install dependencies online** (the default)
On the target machine, double-click `启动遥控器.vbs` → click "Install base dependencies" in the UI.

**Route B: fully offline** (recommended for machines with no network)
On a machine **with a network and the same OS**, download the dependencies as wheels, drop them into the `wheels\`
directory, then copy the whole thing over:

```bat
python -m pip download -r requirements.txt -d wheels
python -m pip download -r requirements-keys.txt -d wheels     :: only needed for key mapping, ~130MB
```

Afterwards, when you click "Install dependencies" on the target machine, the program **automatically detects the
`wheels\` directory and switches to `--no-index --find-links wheels`**, installing fully offline.

**Route C: point at an existing interpreter** (least effort when the machine already has an environment with the
dependencies installed)
Put a `python.txt` in the program directory containing **just one line**: the full path to `pythonw.exe`.
The launcher uses it **first of all**, and if it can't be found it automatically falls through (`.venv` → `runtime` →
system Python), so getting this file wrong cannot break anything.

```
D:\somewhere\vibe-mote\python.txt
→ C:\Users\you\AppData\Local\Programs\Python\Python313\pythonw.exe
```

**Route D: just take the "offline full bundle"** (no Python to install at all, least effort)
`vibe-mote-offline-v1.zip` (~61MB) already bundles a Python runtime and all the dependencies:

```
On the other machine: unzip → double-click "启动遥控器.vbs" → use it
no Python to install, no network (key mapping still needs that one elevation — see README section 5.5)
```

**Route E: supply your own runtime** (when you already have a ready-made Python environment)
Extract the Python embeddable package as `runtime\` in the program directory, and the launch script will use it
first (lookup order: `python.txt` → `.venv\` → `runtime\` → common install locations → PATH).
Note that the embeddable package **has `site` disabled by default** and **has no pip**: for installed
packages to be importable you must enable `import site` in `python313._pth` and add a
`Lib\site-packages` line, with dependencies pre-installed from an external
`pip install --target runtime\Lib\site-packages`. Using the ready-made offline bundle saves you all of this.

> The honest truth about size: a single `frida` file, `_frida.pyd`, is **127MB**, and it cannot be trimmed down —
> key mapping (the D-pad/OK/volume buttons) depends entirely on it. So the "full-featured offline bundle" is about
> 200MB after extraction (61MB compressed). If you only want the voice button, about 15MB is enough, **without
> frida**.

## 6. How to diagnose problems

**Always click "Settings → Environment check" first** — it tells you item by item which layer is broken.

| Symptom | Most likely cause | What to do |
|---|---|---|
| **The frida-helper UAC prompt keeps appearing** | Frida needs administrator rights to register a temporary service for injection; repeated retries produce repeated prompts | "Settings → **One-click optimization (prompts for administrator once)**" fixes it in one go; see section 2.1 |
| **The log keeps printing `Insufficient Authentication` (or `missing ATVV characteristic`)** | The remote's link was never properly **paired/encrypted**: this BLE peripheral insists on an encrypted link | **Remove device** under Settings → Bluetooth & devices, hold 【**Back + Home**】 on the remote to pair again, then click Restart. **No** drivers, no reinstall |
| **Every input level reads 0 / no audio gets in** | The system default recording device is `CABLE Output` (nothing feeds CABLE Input, so every app on the default microphone hears pure silence) | Set it back to the real microphone under Settings → System → Sound → Input; click Settings → Diagnostics → **Microphone self-check** to verify instantly (it prints the default device and the measured peak) |
| **No sound when pressing the voice button right after boot** | At boot the audio service / virtual audio cable is not ready yet | **Wait 5–10 seconds** (the program retries every 5 seconds; the log will say "waiting for the virtual audio cable to be ready…" and then attach automatically) |
| The UI won't open | The client isn't running / the port is taken | Double-click `启动遥控器.vbs` and try again; the port is visible on the "Settings" page |
| The log is flooded with `missing ATVV characteristic` | **Another client is holding the remote's Bluetooth channel**, or this process has a leftover session | Close the other clients (including older versions), then click "Restart". The log prints the service table it enumerated |
| The log is flooded with `connection timeout` | The remote is asleep | **Press any button on the remote**; it connects automatically within 3 seconds |
| Pressing the voice button does nothing, but the log shows `▼ start` | The input method editor does not accept injected keystrokes | Qianwen: click "Turn on Qianwen 'allow injection'"; Doubao: not supported |
| Not even `▼ start` appears for the voice button | Bluetooth is not connected / another client is holding it | Look at the "Voice" channel on the status page; click "Restart" first |
| Chinese text appears even when nobody is speaking | The input method editor has the wrong microphone selected | Choose `CABLE Output (VB-Audio Virtual Cable)` |
| Recognition is choppy, sounds echoed, or there is a constant noise floor | The system default recording device is set to `CABLE Output` (the mic passthrough then feeds that line back) | Set the system default recording device back to your real microphone: Settings → System → Sound → Input. The virtual cable only needs to appear in the **input method editor's own** microphone setting |
| The D-pad/OK do nothing | frida not installed / attach failed | Look at the "Keys" line on the status page; click "Install key-mapping dependencies" |
| Pressing the volume buttons also changes the system volume | In theory it shouldn't (mapped keys have their native action erased at the driver layer); if it happens, that key is **not mapped** | Add it to the mapping table and it is blocked automatically |
| It didn't start automatically at boot | The autostart entry was not written successfully | Turn the switch off and on again on the "Settings" page; the log will report the result |
| **The remote's buttons work, but holding the voice button does nothing / the log keeps saying `connection timeout`** | A Bluetooth LE device accepts only **one** connection and Windows' HID stack sometimes never releases that single link, so the remote stops advertising and the program can never connect | "Settings → Diagnostics → **Reset Bluetooth radio**" (one admin prompt; Bluetooth devices drop briefly). If that fails, take the remote's battery out for 10 seconds |

## 7. What's in the directory

| File | Purpose |
|---|---|
| `启动遥控器.vbs` | **The only entry point** (pure ASCII + CRLF, deliberately without Chinese comments — see the note at the top of the file) |
| `app.py` | All the logic: UI server, configuration, managing the two roles, autostart, environment check, dependency installation |

| `voice.py` | Voice: ATVV voice button + remote microphone → virtual audio cable (pure Python audio, no numpy dependency) |
| `keys.py` | Keys: Frida reads the remote's HID reports out of band → synthesises keyboard/mouse |
| `tap.js` | The Frida script (used for key mapping) |
| `web/index.html` | The UI (single file, zero external resources, works offline) |
| `config.json` | Configuration (generated automatically on first run) |
| `profiles.py` | **The preset table**: application (WorkBuddy / Codex / Claude Code) × input method editor → the whole mapping set. Change key assignments here |
| `uninstall.py` | The cleanup / uninstall script (the UI's "Clean up" button calls it; it also runs standalone on the command line) |
| `elevate_setup.py` | One-off optimization (clear frida leftovers + install the highest-privilege autostart + restart the client with the new code) |
| `python.txt` | **Optional**: which `pythonw.exe` to use (one line, a path). Without it, one is found automatically |
| `.venv/` | **Generated automatically**: the in-package virtual environment created by "Install dependencies" (does not pollute the system Python) |
| `requirements.txt` / `requirements-keys.txt` | Base dependencies / key-mapping dependencies (frida) |
| `wheels/` | Drop offline wheel packages here and offline installation is used automatically (optional) |
| `runtime/` | Drop a Python embeddable runtime here (optional, for deployments that skip installing Python) |
