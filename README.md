## 一、这个版本干净在哪

- ✅ **不装驱动**（没有虚拟 HID、没有内核过滤驱动、不碰 HidHide）
- ✅ **语音部分不需要管理员权限**。按键映射（可选）要**一次**提权 —— Frida 得往蓝牙 HID 驱动宿主里注入、
  并注册一个临时助手服务；点一次「**一键优化**」之后由最高权限计划任务代劳，**之后不再弹**。
  另外就是装虚拟声卡时那一次 UAC（那是声卡安装器自己的要求）。细节见第五节第 5 小节
- ✅ **不弹黑框**：单进程 + 全程隐藏窗口启动，开机自启也一个窗口都不闪
- ✅ **不开测试模式、不关 Secure Boot、不改系统文件**
- ✅ **界面只监听 `127.0.0.1`**，不触发防火墙弹窗
- ✅ **代码极少**：9 个源文件、**第三方依赖只有 3 个**（连 numpy 都不需要）

## 四、第一次使用要做的 3 件事

**界面首页顶部有一张「首次准备」清单**，把这 5 项的状态和按钮都摆出来了，
照着从上到下点一遍就行（不用去「设置」页里翻）：

| 清单项 | 必需？ | 一行说明 |
|---|---|---|
| 运行依赖 | **必需** | bleak / sounddevice（语音）+ frida（按键映射）。点「全部安装」 |
| 虚拟声卡 | **必需** | 语音的物理前提。点「一键安装」 |
| 千问「允许注入」 | 可选 | 用千问输入法才需要；程序**首次启动会自动打开** |
| 开机自启 | 可选 | 一键开关，不需要管理员（想连 Frida 的 UAC 也一起去掉，就再点「一键优化」，那一下要管理员） |
| 一键优化（免 UAC） | 可选 | 做了之后 Frida 不再弹提权框 |

下面是手动的对应步骤：

1. **配对遥控器**：Windows 设置 → 蓝牙和其他设备 → 添加设备 → 同时按住遥控器 **返回 + 主页** 进配对模式
2. **装 VB-CABLE**：界面首页清单或「设置 → **虚拟声卡**」那张卡上点**一键安装** ——
   包内带了官方安装器就直接装，没带会先从官网下载（约 1.3MB）。
   - ⚠ **会弹一次 UAC**（那是声卡安装器自己的要求，与本程序无关），
     然后**在它自己的窗口里点一下「Install Driver」**，最后按 VB-Audio 的官方要求**重启一次系统**。
   - **首次启动时程序会自动帮你把这一步拉起来**（只自动试一次，你拒了 UAC 就不会再烦你）。
     **开机自启拉起的那一份不会弹**（自启命令带 `--boot`）：开机时你不在电脑前，弹了也没人点，
     而且会变成每次开机都弹一次。
   - 官方安装器**不提供静默安装参数**（没有 `-i`/`-s`/`/S` 这类开关），所以"自动"能省掉的只是
     "自己去找那个按钮"，那一下确认和重启省不掉。
3. **输入法里选麦克风**：选 **`CABLE Output (VB-Audio Virtual Cable)`**
   （只改输入法这一处，系统默认录音设备保持真实麦克风）

> ❓ **"虚拟声卡的 in / out 看起来是反的"——不是装反了，是命名角度问题。**
> VB-CABLE 的两个端点是从**线缆自己**的角度命名的：
>
> | 你在 Windows 哪里看到它 | 名字 | 它是给谁用的 |
> |---|---|---|
> | **播放设备**（扬声器那一栏） | `CABLE Input` | **程序往里写** —— 本程序把遥控器的声音写进这里 |
> | **录制设备**（麦克风那一栏） | `CABLE Output` | **程序从它读** —— **输入法要选的就是这一个** |
>
> 所以：**输入法的麦克风列表里只出现 `Output`，是完全正确的** ✓（输入法在"录"）；
> 而"程序往 `Input` 写"那一端你在麦克风列表里永远看不到 ✓。
> 链路是：`遥控器麦克风 → 本程序 → CABLE Input（播放）→ 虚拟线 → CABLE Output（录制）→ 输入法`。
> 没声音时按这个顺序查：① 本程序日志那行「音频出口已开启 → 写入「CABLE Input…」」在不在；
> ② 输入法选的是不是 `CABLE Output`；③ **`CABLE Input` 和 `CABLE Output` 两边的音量和静音**
> （重装声卡后常有一侧被静音或音量 0）。
> 想立刻验证：`设置 → 诊断 → 麦克风自检` 会把这两个名字和实测峰值一起打出来。

> **千问输入法用户不用做任何事**：千问默认会丢弃程序注入的按键，所以程序在**首次启动时
> 会自动帮你打开**「允许注入」开关（写用户环境变量、重启一次千问进程，不需要管理员）。
> 这个开关随时能在「语音」页手动开关 —— 你在「清理」里删过它的话，程序会记住、
> 不再自动加回来，想恢复点那个按钮就行。

## 五、它到底会动你电脑的什么（完整清单）

这是问得最多的一个问题，所以把话说全 —— **程序本体是纯绿色部署**：不装驱动、不写系统目录、
不需要管理员常驻（**按键映射要一次提权，以及它带来的限制/风险，单独写在第 5 小节**）。
下面是它**全部**会碰的东西，一项不漏：

### 1. 写在程序自己的目录里（删掉整个目录就没了）

`config.json`（配置）· `client.log`（日志）· `uninstall.log` · `qwen_optout`（你删过千问开关的标记）
· `cable_autotried`（自动装过声卡的标记）· `_ready.txt` · `_deferred_result.txt` · `_uninstall_result.json`

### 2. 系统里的设置改动 —— **每一项都是你自己点出来的，且都能一键撤销**

| 动什么 | 什么时候会动 | 怎么撤 |
|---|---|---|
| `HKCU\...\CurrentVersion\Run\VibeMote` | **只有**你打开「开机自启」 | 界面关掉，或清理清单里勾那一项 |
| 最高权限计划任务 `VibeMote` | **只有**你点「一键优化」 | 清理清单里勾「取消开机自启（计划任务）」 |
| `HKCU\Environment\QIANWEN_IME_UTILITY_VOICE_HOOK_ALLOW_INJECTED=1` | 装了千问输入法时自动写（也可以不写） | 界面按钮，或清理清单里勾那一项 |
| Frida 的临时助手服务 `frida-<pid>-x86*` | **Frida 自己**在挂载时注册的 | 清理清单里那一项；点过「一键优化」之后不再需要 |

**不做的事**（写下来是为了让你放心）：不装驱动、不碰 `System32` / `Program Files`、
不改输入法在注册表里的配置、不开测试模式、不动 Secure Boot、不关 Defender、不常驻管理员。
联网只有两处：你自己点「安装依赖」，或点「安装虚拟声卡」而包内没带安装器时（去 VB-Audio 官网下）。

### 3. 唯一会动到系统深处的两件事：**都由第三方安装器完成，程序只是替你启动它**

| 东西 | 谁装的 | 需要什么 |
|---|---|---|
| **VB-CABLE** 虚拟声卡（内核音频驱动） | **VB-Audio 自己的安装器** | 一次 UAC + 重启 |
| **Frida** 的助手进程 | Frida 自己的机制 | 首次挂载一次 UAC |

> ⚠ **必须提前知道的一件事：VB-CABLE 官方的卸载器卸不干净。**
> 点「Remove Driver」并重启之后，驱动可能**仍然存在**（设备管理器里状态正常、音频端点全部重新出现）。
> 原因是它留下了 DriverStore 里的驱动包、`C:\Windows\inf\oem634.inf` 和几个服务键，
> Windows 重启时照着又装了回去。
> 想**真正**删掉，得再跑一次管理员命令：
> ```
> pnputil /delete-driver oem634.inf /uninstall /force
> ```
> （`oem634.inf` 这个编号每台机器可能不同，用 `pnputil /enum-drivers` 找
> `Original Name: vbmmecable64_win10.inf` 那一条。）
> 这是 VB-Audio 卸载器自己的行为，与本程序无关 —— 但界面会照实说明，不会假装删干净了。

### 4. 会不会把别人的电脑弄坏？

不会。它没有内核驱动、不注册自己的常驻服务（Frida 挂载时会临时注册一个**助手服务**，点过「一键优化」
之后连这个都不需要）、不写系统目录，最坏情况只是"某个功能不工作 + 一条日志说明为什么"。
真正需要小心的两点已经在上面写明了：VB-CABLE 的安装/卸载要 UAC + 重启（那是它的要求），
以及清理时**默认什么都不勾** —— 只有你自己勾了才会删东西。

> 另外提醒：**同一时间只能有一个客户端连这个遥控器**（遥控器只给第一个客户端完整的服务表）。
> 如果你机器上还跑着别的同类工具，本程序会报「缺少 ATVV 特征」。先关掉其它客户端再试。

### 5. 已知的限制与风险（宁可提前说，不藏在角落里）

**按键映射（方向键/OK/音量那些）和语音是两套东西，代价也不一样：**

| | 语音（遥控器说话 → 出字） | 按键映射（14 个键 → 键盘/鼠标） |
|---|---|---|
| 需要管理员吗 | **完全不需要** | **需要一次提权**：Frida 要往蓝牙 HID 驱动宿主里注入，并注册一个临时服务 |
| 靠什么实现 | 普通蓝牙 GATT 连接 | 在**内存里**钩住那个驱动宿主（重启就没了），并把**被映射那几个键**的原生动作抹掉 |
| 不装 frida 会怎样 | 照常工作 | 这个功能不可用，其余一切正常 |

- **爆炸半径**：注入的是**蓝牙 HID 驱动宿主**，它同时服务你其他的蓝牙键鼠。我们只改被映射那几个键的
  报文，但万一这个宿主崩了，**蓝牙键鼠会一起掉线**（实测没遇到过；真发生就重启客户端或拔插一下适配器）。
- **依赖未公开接口**：按键映射用的是 Windows 蓝牙 HID 驱动的一个**未公开 IOCTL** 和一个注册表路径，
  并锁定 `frida >=17.18,<18`。Windows 或 frida 更新后它**可能静默失效** —— 失效时程序会优雅降级：
  语音照常，按键映射停用并在日志里说明。
- **杀软可能误报/误隔离**：frida 的模块名（`frida-agent.dll`、`frida-helper-*.exe`）在多家 AV 的特征库里。
  离线包约 61MB，其中 frida 约 47MB —— 被静默隔离的话，解压出来"按键映射"就是坏的（用户会以为是我们 bug）。
  症状：界面「安装按键映射依赖」后 `keys.ready` 一直 false、或日志说找不到 frida。
  处理：把程序目录加进 AV 白名单，或重新装一次依赖。我们**不会**让你关 Defender、开测试模式。
- **受保护的游戏**：往 SYSTEM 进程里注入这件事，行为特征和作弊器加载器同类。少数带内核反作弊的游戏
  可能因此起不来或报错 —— **玩游戏前把客户端退出**（或至少别用按键映射）是最省事的做法。
- **许可**：frida 是 wxWindows 3.1（LGPL-2.1+ 例外），随包分发合规，细节见
  [`THIRD-PARTY-NOTICES.md`](THIRD-PARTY-NOTICES.md)。

## 六、下载源（国内没 VPN 也能装）

包内 wheels（纯离线）→ 腾讯云 → 中科大 USTC → 阿里云 → 华为云 → 清华 TUNA → 官方 PyPI

## 七、出问题

界面「设置 → **环境体检**」会逐项告诉你哪一层断了（依赖 / 声卡 / 蓝牙 / 权限 / 自启 / 千问开关）。
「日志」页是实时流，报 bug 时把那段贴出来就够了。

| 现象 | 原因 | 解决 |
|---|---|---|
| 日志刷 `连接超时` | 遥控器在休眠 | **按一下遥控器任意键**，3 秒内自动连上 |
| 日志刷 `缺少 ATVV 特征` | 有另一个客户端占着蓝牙通道 | 关掉其它客户端再点「重启」 |
| **所有麦克风电平都是 0、声音进不去**（电脑麦克风阵列和遥控器都一样） | **系统默认录音设备被设成了 `CABLE Output`** —— 而没人往 CABLE Input 灌声音，于是所有「用默认麦克风」的程序收到的都是纯静音 | 「设置 → 系统 → 声音 → 输入」把默认设备改回**真实麦克风**（虚拟声卡只该出现在**输入法自己的**麦克风设置里）。点一次「设置 → 诊断 → **麦克风自检**」，它会报出默认设备和实测峰值，一眼看出是不是这个问题 |
| 按语音键没反应 | 千问的「允许注入」没开 | 「语音」页点一下那个按钮 |
| **方向键 / OK / 音量没反应**，日志反复写 `挂载失败：TransportError: the connection is closed` | **杀软 / EDR 拦了注入**（**公司电脑上最常见**：安全软件掐断 Frida 的注入通道） | 请 **IT 把程序目录加进杀软白名单**（我们不改系统设置、不关 Defender）。放行之前**语音照常可用**，只有按键映射不行。点一次「设置 → 诊断 → 按键映射自检」，它会把这行证据写进日志 |
| 日志刷 `GATT Protocol Error: Insufficient Authentication`（或一直「缺少 ATVV 特征」） | 遥控器的链路没完成**配对/加密** —— 蓝牙外设坚持要一条已加密的连接 | 「设置 → 蓝牙和其他设备」把遥控器**删除设备** → 按住遥控器【**返回 + 主页**】重新配对 → 回程序点「重启」。别动驱动、别重装程序 |
| **用着用着发现客户端没了 / 开机没自动起** | 计划任务只在**登录那一刻**跑一次，进程异常退出后没人拉它回来 | 点一次「设置 → **一键优化**」重建任务：新版任务带**每 5 分钟自检**，进程万一挂了最多 5 分钟自动回来（已经在跑时新进程秒退，不弹窗不刷日志） |
| **蓝牙设备全没了 / 设置里连"蓝牙"开关都不见了** | 蓝牙**电台被禁用了**（Windows 的蓝牙开关本质就是禁用那个 USB 电台；关掉后忘记开回来、或设备管理器里禁用过） | 一、`Win+X → 设备管理器 → 蓝牙` → 右键 `Intel(R) Wireless Bluetooth(R)` → 「**启用设备**」；二、不行就**完全关机**（开始菜单「关机」，不是重启）再开机；三、新版客户端里点「设置 → 诊断 → **重置蓝牙电台**」也会先帮你把电台启用回来（只启用，不会再关开）。**不是硬件坏了，设备都在** |
| 刚开机没声音 | 音频服务/声卡比程序晚就绪 | **等 5~10 秒**（程序每 5 秒重试，会自己接上） |
| 日志刷 `缺少 ATVV 特征`、界面显示的还是旧配置 | 多半有**两个实例**同时活着抢蓝牙 | 点「重启整个客户端」即可 —— 现在它会**把本目录里所有旧实例一起结束掉**（不再只看谁占着端口），只保留新起来的那一个 |
| 装虚拟声卡时报 `Unknown Error 1072` | 那个服务停在「待删除」状态（之前清残留只删了服务、没先停驱动）—— 它提示"请用管理员运行"是误导，你本来就是管理员 | **重启一次**，再点「一键安装虚拟声卡」；还不行就把 `vbcable\VBCABLE_Setup_x64.exe` 右键「以管理员身份运行」点 Install Driver |

程序会把启动日志写到同目录的 `client.log`；启动失败时启动器会弹提示并自动打开它。

## 八、卸载

两步，顺序别反：

1. 界面「设置 → 清理 / 卸载」点「选『推荐清理』」→ 开始清理（断开机自启 + 清 frida 残留服务 + 删依赖）；
2. 然后**直接删掉整个程序目录**。

程序是纯绿色部署（没有安装器、不写系统目录），第 ② 步之后系统里不会有任何残留。

**虚拟声卡不在这两步里，要单独说一句**：清理清单里有一项
「卸载虚拟声卡（VB-CABLE）」，但**默认不勾、也不属于「推荐清理」** —— 理由是
它是**系统级音频驱动**，OBS / 变声器 / 直播工具可能也在用它。真要卸的话：

- 勾上它 → 清理时会弹一次 UAC 并**启动官方的卸载器**，
  你还要在它窗口里点一下「**Remove Driver**」；
- 按 VB-Audio 的官方要求，**卸完必须重启一次**系统才算卸完。
- 所以它是清单里唯一一个"点完还要人动手 + 重启"的项，日志里都写明了。

**装/卸卡住了怎么办**（注册表里显示装了、设备却枚举不出来，点 Install Driver 没反应）：
清理清单里还有一项「**清除虚拟声卡残留（注册表 / 驱动包）**」，默认也不勾。
它只删 VB-CABLE 自己的那几处（两个服务键、`HKLM\SOFTWARE\VB-Audio\Cable`、
「应用和功能」里那条、DriverStore 里的驱动包、`C:\Program Files\VB\CABLE`），
**同属 VB-Audio 的 Voicemeeter 的键和目录一个都不会碰**。清完**重启一次**，再点「一键安装虚拟声卡」。
（首页出现「虚拟声卡现在用不了」那个黄色横幅时，旁边的按钮就是它。）

## 九、遥控器怎么挑（原装 / 兼容款 / 山寨）

这个工具依赖遥控器的**两个能力**，而它们**不一定同时存在**：

| 能力 | 用在哪 | 怎么判断 |
|---|---|---|
| **ATVV 语音服务**（`ab5e0001`，音频 `ab5e0003`） | 按住说话 → 输入法出字 | 日志里没有「缺少 ATVV 特征」就是有 ✓ |
| **标准 HID 按键报文**（3 字节 Consumer Control） | 方向键 / OK / 音量等映射 | 日志「按键映射：挂上蓝牙驱动宿主 … ← 设备 `…_Dev_VID&0218d1_PID&9450_…`」 |

**实测（2026-09-15，两支都标着「G9N9N / GA01919」的兼容款）**：

- 一支正常：设备报告 **VID `18D1` / PID `9450` / REV `011b`**（跟原装一致），语音 + 按键都能用 ✓
- 另一支失败：GATT 直接报 `Insufficient Authentication`，服务表里**只有 4 个通用服务**（没有 `ab5e…`）
  → 语音不可能工作 ✗；**换一支同款就正常了** ✓

结论：**同一链接、同一型号的兼容款，不同批次能差很多**。挑的时候：

1. 先问卖家「**支持语音（ATVV）吗**」「是不是原装 G9N9N / GA01919」；
2. 到手就看日志那行**设备身份**（`VID&0218d1_PID&9450` 是与原装一致的表现 ✓）；
3. 如果日志直接说「这台遥控器**没有语音服务**」→ 别怀疑软件，**退换货**。

**已知可用**：原装 **G9N9N**（Chromecast with Google TV 语音遥控器）、
**Google TV Streamer（2024）遥控器**（Google 说它兼容 2020+ 的 Chromecast，但本项目**未实测**）。
**风险款**：十几块钱的「适用谷歌」兼容款 —— 能用的不少，但批次差异大，按上面三步挑。
